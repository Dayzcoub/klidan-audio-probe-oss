# Test safety and evidence policy

## Test classes
1. **Passive:** enumeration, property reads, `GetMixFormat`, `IsFormatSupported`. Existing code. No stream `Initialize` or `Start`.
2. **Active stream tests (`--test-stream`, `--test-duplex`):** explicit operator opt-in, Exclusive `Initialize/Start/Stop`, duration bounded to 1–30 seconds, bounded event waits, no saved capture samples; Render sends only silence. Duplex uses independent COM/WASAPI ownership per servicing thread, prepares both clients before Start, and stops both sides on failure or cancellation. It does not route Capture to Render. These tests may reserve Exclusive access and interrupt another application. Abort safely on unplug/format rejection/timeouts.
3. **Live transport (`--test-monitor`):** explicitly routes transient Capture PCM16 stereo frames to the selected Render endpoint, only with `--confirm-live-output`. It is bounded to 1–30 seconds, fixed at −24 dB software gain, 48 kHz Stereo PCM16, and never records samples or creates test signals. It starts Render with silence and continues with silence for prefill/underruns; critical errors or cancellation stop both workers. Before the first physical test, use headphones, minimum hardware output volume, and acoustically isolate the output from the microphone. Acoustic feedback remains possible; the software gain is not a safety guarantee. No physical test runs automatically.
4. **Synthetic monitor transport timing (`--test-monitor-latency`):** requires both `--confirm-live-output` and `--confirm-test-signal` before COM/device access, is fixed at five seconds / 48 kHz Stereo PCM16, and never reads or routes Capture sample memory. It substitutes a deterministic −36 dBFS marker sequence in preallocated staging after Capture packet acquisition; the existing −24 dB ring gain limits Render output to about −60 dBFS peak on L, with R zero. Use headphones, minimum hardware output volume, and first disconnect any analog loopback cable. It does not form a physical feedback loop. Provenance uses extra bounded metadata per slot of the same SPSC ring, not a second queue. Any timestamp/continuity fault, ring underrun/overflow, critical worker error or cancellation stops the peer; Render's current and subsequent buffers are silenced. No test samples are saved.
5. **Capture channel meter (`--meter-capture`):** requires one explicit `--capture-id`, `--confirm-live-capture`, and a bounded 1–30 second duration before endpoint activation. It supports only exact 48 kHz PCM16 mono/stereo, checks `IsFormatSupported` and Exclusive `Initialize` before `Start`, and meters then discards Capture PCM in memory. It never opens Render, routes audio, or saves raw samples. `Ctrl+C`, device loss, or API failure stops Capture; cleanup is reported. A local sanitized JSON report is optional and refuses overwrite. Windows speaker labels from a channel mask identify Windows channel positions only; they do not identify physical mixer sockets. Meter levels are digital dBFS, not acoustic calibration. No meter or hardware test runs automatically.
6. **Render channel signal (`--test-output-channel`):** requires one explicit `--render-id`, `--render-channel 1|2`, both `--confirm-live-output` and `--confirm-test-signal`, and a 1–10 second duration before endpoint access. It is fixed to exact 48 kHz Stereo PCM16 Exclusive, requires `IsFormatSupported(S_OK)` and successful Initialize before Start, primes with silence, then emits a gated 997 Hz sine no higher than −36 dBFS on only the selected Windows channel. The other channel is initialized to digital zero. At normal completion, the signal switches to zero on a regular Render event when the deadline is within one buffer period; cancellation/failure stops generation and promptly calls Stop without requesting another buffer. It never opens Capture, Ring, or monitor routes. Keep external amplification low; digital channel selection does not establish physical socket routing or audibility. ReleaseBuffer means software submission, not DAC playback. No test runs automatically; JSON remains sanitized and refuses overwrite.

Never run active capture/output during launch, discovery, CI, unit tests, or an unattended probe. Do not run `--test-monitor` or `--test-monitor-latency` until an operator explicitly launches the corresponding confirmed test.

The optional `--mmcss pro-audio` setting registers only the servicing thread for the `Pro Audio` task before `Start`, and reverts that registration after stopping. Registration failure must prevent `Start`; it never changes system priority settings or silently falls back. Capture device/QPC positions are diagnostic packet timestamps only, not proof of dropped acoustic frames or a round-trip latency measurement.

The Duplex-only `--clock-probe` option samples each worker's own `IAudioClock` after event servicing, approximately every 250 ms, into a pre-reserved bounded buffer. It saves no audio. `GetPosition` `S_FALSE` samples and failed calls are rejected and reported; invalid/nonmonotonic timestamps suppress regression. Clock estimates are diagnostic Windows/driver timestamp correlations and do not prove hardware clock drift, absolute phase, or RTL. See [IAudioClock](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nn-audioclient-iaudioclock) and [GetPosition](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition).

The explicit `--test-analog-loopback` is an active low-level physical output test. It requires both `--confirm-test-signal` and `--confirm-physical-loopback` before any endpoint activation; a missing confirmation exits before COM/device access. It is limited to five seconds, 48 kHz Stereo PCM16, a selected Capture and Render channel, and a fixed PRBS marker whose peak does not exceed -36 dBFS. Only the selected Render channel carries the marker; the other is zero. Captured samples remain in a bounded preallocated buffer, are used for analysis, then overwritten and released. No samples are written to files. A hardware/API failure or Ctrl+C stops both workers.

For the documented Audient iD4 cable test, connect **Line Out L → TRS cable → Line Input 1**. Disconnect microphones, 48 V phantom power, speakers and direct hardware input monitoring before starting. Do not connect the line output to an XLR microphone input. The Audient software Loopback Mixer is not a physical analog loop. Check the cable path and use a conservatively set input gain; test output is low but does not replace safe physical setup. Never run this mode automatically or from CI.

Timing alignment uses the Render `IAudioClock::GetPosition` stream position/frequency and its paired QPC timestamp; Capture uses each packet's device position/QPC timestamp. The two mappings are fitted/validated against their shared QPC axis, so asynchronous WASAPI `Start` calls do not require matching frame-index origins. Poor clock fits, packet gaps/discontinuities, timestamp errors, clipping, ambiguous/weak marker correlation or incomplete streams prevent `LOOPBACK_STATUS: MEASURED`. An unreliable result includes raw marker offsets where detectable and `TIMING_ALIGNMENT_UNRELIABLE`; reported device period and `GetStreamLatency` are never substituted. The estimate is physical Render→DAC→analog cable→ADC→Capture path delay, not B4-A Live Monitor delay, driver-only latency or acoustic loudspeaker latency. A clean result does not establish long-term stability or calibrated absolute uncertainty.

### B4-B2B.1 capture-only RTL preflight

`--test-monitor-rtl-preflight` is a five-second, explicit Capture-only test for 48 kHz Stereo PCM16. Before COM/device access it requires `--confirm-live-capture`, `--confirm-physical-routing`, `--confirm-test-signal`, `--confirm-safe-setup`, and the exact source declaration `--test-signal klidan-prbs511-v1`. It opens only the selected Capture endpoint, starts Capture, stores at most six seconds of interleaved PCM in preallocated memory, analyzes it after the bounded run, then zeroes/releases the samples. It never activates or starts a Render endpoint, never pushes PCM into the SPSC ring, and cannot measure RTL. It can reach `ARMED` only after at least five coherent markers on Input 1, Input 2 peak at or below −40 dBFS, at least 99% nominal frame coverage (237,600 of 240,000 frames for the supported configuration), no clipping, no timestamp errors, no discontinuity or device-position gap, and a complete bounded run. The 1% coverage allowance bounds stream start/stop edge loss to 50 ms. Ambiguous/missing signal fails closed. Cancellation, watchdog, API failure or device invalidation cannot start Render.

The separately unit-tested preallocated stereo staging maps Capture Input 1 to Render L and writes literal zero to every Render R sample; Capture Input 2 is reserved to analysis. Invalid pointer/size/format/state returns an error after zeroing the available Render span. This route is not activated by B4-B2B.1; `ROUTING_ISOLATION_STATUS` reports that Render was not active. Preflight does not itself prove physical connector routing or switch state.

For target Audient iD4 MKII, the vendor describes Input 1 as rear mic/line and Input 2 as front JFET instrument input; the published specifications give line-output lineup of +12 dBu = 0 dBFS but do not state a maximum D.I input level. A direct Line Out→Instrument Input connection is therefore not approved by this software stage. Before any future Render test, the operator must establish a safe level-matching/attenuator arrangement and confirm the physical route; disable phantom power, direct monitoring and speakers. See [Audient iD4 MKII connections](https://docs.audient.com/id4/hardware-connections/) and [technical specifications](https://support.audient.com/hc/en-us/articles/360055048851-iD4-MKII-Technical-Specifications).

### B4-B2B.2A offline analyzer boundary

The dual-channel RTL analyzer is synthetic/offline only. It accepts bounded PCM16 Stereo and packet metadata in memory, never enumerates or activates endpoints, and is not exposed as a live CLI mode. Synthetic delay is reported on a common Capture frame timeline; differential Input 1/Input 2 hardware delay remains unknown, so the physical RTL state is always `NOT_MEASURED`. Synthetic validation cannot authorize cabling, output or a physical test.

Routing tests use synthetic frames through the existing Input-1-only staging and unchanged SPSC ring. They prove the staged/render right channel is zero and Input 2 cannot enter either Render channel in that tested transform. They do not invoke a WASAPI Render worker. Audient iD4 MKII line output to Input 2 still requires an independently reviewed level-matching/attenuation fixture: the published +12 dBu line-output lineup does not specify the D.I input's maximum safe level. No physical approval is implied.

### B4-B2B.2B disarmed session

`MonitorRtlSession::Coordinator` is synthetic-only and has no CLI mode, endpoint IDs, COM interfaces, endpoint activation or WASAPI Render calls. A test harness must explicitly inject readiness fields marked `simulated`; these only exercise the software lifecycle and are never physical approval. The coordinator configures a new empty SPSC ring before processing, bounds the five-second PCM/packet/output storage, routes through the existing staging buffer, and services only a fake Render sink. Ring Push/Pull/gain/prefill behavior is unchanged; cleanup uses a post-stop slot erase after both simulated participants have stopped. Input 2 goes to bounded analyzer storage only; every fake Render R sample is checked as digital zero. On fault/cancel it stops packet acceptance, silences and erases transient PCM, and releases the ring only after processing has stopped. The analyzer runs after ingestion has stopped. Automated tests exercise synthetic data only and do not activate or start any real Capture or Render endpoint.

### B4-B2B.2C mocked Runtime Safety Gate

`RuntimeSafetyGate` is control logic only. Its mock adapters never initialize or start WASAPI, and its output inhibit starts `OUTPUT_DISABLED`; `OUTPUT_ARMED` also remains disabled. The shared-start decision only requests both workers. Non-silent PCM is accepted by the fake sink only after both workers independently acknowledge successful startup for that session, in addition to fresh Capture/Render observations, transport/routing checks and operator declarations. Duplicate, invalid or late start acknowledgements fail closed. The gate rejects stale or replayed observations, identity/format/period/buffer changes and the generic stereo monitor route. It permanently reports `SIMULATION_STATUS: MOCKED`, `HARDWARE_QA_STATUS: NOT_RUN`, `PHYSICAL_RTL_STATUS: NOT_MEASURED`.

Cancellation, worker/API faults, endpoint invalidation, ring faults, routing/timestamp faults, explicitly reported watchdog/peer timeouts and invalid transitions inhibit the sink and request both workers to stop. A cleanup attempt before both worker owners acknowledge quiescence remains waiting; it is not itself evidence of timeout. Each worker owner must acknowledge quiescence before resource reclamation; failure/cancellation does not bypass this barrier. Late events cannot re-enable output. This mock gate is not hardware authorization and cannot prove physical switches, cabling, attenuator safety or actual stream readiness. A real Render stop cannot retract audio already submitted to a device. For Audient iD4 MKII, direct Line Out L → Input 2 remains unapproved: Input 2 is an instrument/DI input and current evidence does not establish its maximum allowable level. Software gain/limiting is not electrical protection. No cabling or physical output test is authorized by this phase.

### B4-B2B.2D Capture-only evidence

The explicit `--test-monitor-rtl-preflight` command is the only active Capture path used to collect new runtime evidence. It retains the existing four confirmations, fixed five-second PCM16 Stereo 48 kHz configuration and signal thresholds. Runtime evidence is finalized only after Stop, Capture service/client/event cleanup and endpoint release. Automated tests use synthetic facts and the existing in-memory packet collector; they must not activate an endpoint.

The adapter has no Render endpoint/client/service, Render `Start`, Ring Push, or live-monitor connection. A direction/route guard rejects Render, SPSC, and monitor/loopback combinations before client activation. Reports redact endpoint IDs and show `OUTPUT_DISABLED`, `RENDER_STATUS: NOT_STARTED`, `HARDWARE_QA_STATUS: NOT_RUN`, and `PHYSICAL_RTL_STATUS: NOT_MEASURED`. Capture evidence does not approve any physical fixture or authorize future output.

## Accurate result names
- `reported_supported`: only `IsFormatSupported(S_OK)`.
- `initialize_succeeded`: `IAudioClient::Initialize` actually succeeded.
- `started`: `Start` succeeded.
- `frames_observed`: frames were observed via capture/render API.
- `stream_completed_with_warnings`: bounded run ended after `Start`/`Stop`, but reported recoverable anomalies such as discontinuities or long event intervals.
- `stable_for_duration`: timed run with explicit zero/nonzero faults/drops.
- `round_trip_latency_measured`: physical/tested loopback measurement, not `GetStreamLatency`.
- `klidan_verified`: separate end-to-end operator acceptance with exact app version.

A `null` / unknown field is not PASS. No successful tests may be inferred by analogy from another device, transport, channel layout or driver version.

## Diagnostics and cleanup
- Preserve the full HRESULT and original format descriptor; distinguish unsupported format, device busy, buffer alignment, device invalidation and generic failure.
- Bounded candidate list, retries, test duration and output; no infinity loops.
- COM ownership/release on the correct thread, unambiguous stop/error state, always stop and release even after an exception/fault.
- Audio/realtime thread: no dynamic allocations, disk I/O, logs, IPC, COM activation, UI messages or endpoint enumeration. Publish bounded atomic status snapshots.
- Do not modify system sample rate, default audio device, interface gain, routing, loopback monitoring or driver settings automatically.

## Privacy
Endpoint IDs, container IDs, USB serials, machine names, user paths, device instances and raw audio can be sensitive. Reports default to sanitized/public-safe device descriptors; full raw endpoint IDs are local transient working state. Full diagnostic exports require deliberate local opt-in and must be clearly labeled. No network submission by default.

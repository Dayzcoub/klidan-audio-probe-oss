# D3-B2.1 — Operator workflow redesign

**Status:** implemented in the WPF shell; no hardware/visual operator QA performed in this task.

## Primary route

The Windows diagnostic path is presented as **Device → Test → Result**. Device is the initial view. Worker connection and MMDevice discovery require separate operator actions; no endpoint scan or audio operation starts on launch. Search, direction/state filters, exact endpoint identity, reported topology, and the existing endpoint inspector remain attached to the selected Windows endpoint.

The test step offers the existing real **Exclusive format query** and **Initialize-only** validation. Live Capture Meter and Live Render Channel Test remain future capabilities. If Initialize-only is selected before a current query exists, the page explains the prerequisite and enables the passive query there while preserving Initialize-only mode. A successful query stays on the Test step; the operator must then select a supported format and `DEFAULT` or `MINIMUM` period and provide fresh, one-use consent. Initialize is never automatic. Changing endpoint, format, or period invalidates pending consent. Any endpoint selection change or rediscovery permanently marks the previous query historical for this selection; selecting the old endpoint again does not revive its authorization.

The unique-format table requires exactly one `default` and one `minimum` record for each requested encoding/rate/channel combination. Support status, `IsFormatSupported` HRESULT, and shared query/cleanup evidence must agree across both periods. Missing, duplicated, unrequested, malformed, or contradictory records are shown as `INCOMPLETE/CONFLICT` with their evidence and cannot authorize Initialize-only. A failed refresh leaves the earlier matrix viewable as historical evidence, but that matrix is not current and cannot authorize Initialize.

Periods are initialization settings; they are not independently queried or validated by the passive query. Query and Initialize results remain bound to the exact endpoint ID and direction returned by the worker; the friendly name is presentation only.

### D3-B2.2 format selection

The format table sorts driver-reported support first, followed by unsupported, not-tested, incomplete/conflict, and failed results. A successful query selects the first eligible supported format only when the existing selection is absent or no longer eligible; a valid manual selection and period survive refresh. No query auto-runs Initialize. A compact count summary keeps query outcomes and Initialize status separate. A visible Russian explanation states why Initialize-only is unavailable. The result step presents device, format, reported support, requested period, Initialize status/HRESULT, buffer, event readiness, and cleanup evidence first; detailed HRESULT, alignment retry, and COM release data remain in a collapsed technical section.

Initialize-only continues to use the existing worker/native implementation, timeout, and worker-termination behavior. It calls no `Start`, obtains no PCM, and does not establish a running stream or observed audio. The result view keeps command outcome, support status, Initialize result, and audio-operation states separate. A worker/discovery loss does not turn an unknown result into success. The last confirmed result remains available while navigating, including after selecting another endpoint.

User-initiated JSON export is not included: the existing real result DTO carries a local endpoint ID and this slice does not define a sanitized export schema. No persisted report history is implied.

## Developer Tools

Local Demo, Worker Fake, synthetic sessions/reports, local format fixtures, and raw worker/IPC diagnostics remain available under **Developer Tools**. The real Windows operator flow is outside that section. No fake result is used as real WASAPI evidence.

## Verification

GUI Core tests exercise the three-step state, explicit discovery/query, Capture/Render mode filtering, 12-row grouping from 24 period records, consent cancellation on period changes, query failure, result identity retention, Developer Tools isolation, and runtime WPF panel/ComboBox bindings. Windows STA layout checks cover 1024×720, 1280×800 and 1440×900 DIP. Release validation: GUI build succeeded with zero warnings/errors; 286 GUI Core checks, 199 Worker IPC/process checks, and 106 native CTest cases passed. The running-app accessibility tree was inspected at startup and showed Windows metadata provenance with no automatic discovery. Interactive screenshot review and DPI-scale testing were not performed, so visual/DPI QA remains pending.

No endpoint discovery, `Initialize`, `Start`, Capture, Render, or PCM operation was run during implementation or validation.
